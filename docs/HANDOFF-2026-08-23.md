## One premise to confirm

Project notes record the substrate decision as: pin the upstream commit and
write the executable contract, explicitly **not** vendor or fork. The tree now
contains `akkar/vendor/http/`, holding the HTTP/1.1 half of lua-http, added in
`0b3750e` and then optimised in place (`8e9f9cd`, `6addb0e`, `ed23e89`,
`4363754`, each trading vendoring for bytes per request).

Whether that was a deliberate reversal of the substrate decision, or vendoring
adopted as a means to the allocation work with the decision never rewritten,
is unresolved. It matters because "the public API never depends on the
substrate implementation" (`docs/PLAN.md` section 1) is the rule the vendored
copy is now on the wrong side of.
